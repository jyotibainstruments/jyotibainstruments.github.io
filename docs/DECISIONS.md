## Phase 1 — foundation

- **2026-11-06 — Deployment target.** Confirmed by the owner: user site at `https://jyotibainstruments.github.io`, `base: '/'`. `ASTRO_SITE` and `ASTRO_BASE` remain environment overrides.
- **2026-11-06 — Astro 7.4.7.** Current stable at build time. The brief was written against an older Astro. Changes applied:
  - `compressHTML: true`, because Astro 7 defaults to `'jsx'` whitespace handling and can drop spaces between inline elements.
  - The Rust compiler is strict about unclosed tags and invalid nesting; templates will be written accordingly.
  - `output: 'static'` remains valid.
- **2026-11-06 — TypeScript 6.0.3, not 7.x.** `@astrojs/check` peers on `typescript@^5 || ^6`; TypeScript 7.0.2 is outside that range. Pin 6.0.3.
- **2026-11-06 — `@astrojs/check` added.** `astro check` requires it, but the Phase 1 install list omitted it. It is a dev dependency.
- **2026-11-06 — `@lhci/cli` and `linkinator` added.** Phase 1 requires `links`, `lighthouse` and `audit` scripts, which need these dev dependencies. No other packages were added.
- **2026-11-06 — Zod 4.6.7 installed directly.** It matches the version Astro 7 already depends on, so npm dedupes it. Office data is validated at build; a bad entry fails the build.
- **2026-11-06 — Offices live in `src/data/offices.json`.** `src/config/site.ts` imports and re-exports them, so phone numbers and addresses have one source. This satisfies the Phase 1 requirement that `site.ts` exposes offices without duplicating facts.
- **2026-11-06 — Fonts vendored from Fontsource.** The Fontsource variable CSS includes every subset. The two latin variable WOFF2 files were copied into `src/assets/fonts/`, with their OFL licences, and declared with `@font-face` in `global.css`. This keeps the site latin-only, self-hosted, cacheable and preloadable. No external font requests.
- **2026-11-06 — Focus ring: gold with a crimson keyline.** Owner approved. The ring is 3px gold plus a 1px `--crimson-900` keyline (white on crimson surfaces). Pure gold is 2.4–2.6:1 against `--bg`/white, below the 3:1 non-text contrast requirement in WCAG 2.2 SC 1.4.11. The keyline keeps the brand's gold ring while providing a compliant boundary. Lighthouse will not catch this; it needs manual review.
- **2026-11-06 — Logo master.** `design/jie-logo-original.svg` is the only master, optimised with SVGO into `src/assets/brand/jie-logo.svg`. Fills are preserved (`#111111`, `#76122E`). `design/JIE_logo_sharp_vector_clean.svg` is a reconstruction with a baked-in white background and is not used. A white footer version will be produced with a CSS filter in Phase 2, not by recolouring the file.
- **2026-11-06 — No `favicon.ico`.** `sharp` cannot emit ICO. The site ships `favicon.svg`, 32px and 192px PNGs, and `apple-touch-icon.png`, which current browsers accept.
- **2026-11-06 — Generated `logo-512.png`.** Used for `Organization`/`LocalBusiness` JSON-LD, because search engines prefer a raster logo with a stable size.
- **2026-11-06 — Prefetch is global.** `prefetchAll: true` with the `hover` strategy. The brief asks for hover prefetching; Astro's `prefetchAll` defaults to `false`, so `defaultStrategy` alone would prefetch nothing.
- **2026-11-06 — Link checks skip the production origin.** Absolute canonical/JSON-LD URLs point at the not-yet-deployed domain. `npm run links` checks the local build and skips `https://jyotibainstruments.github.io` so it does not test the live site. Revisit after launch.
- **2026-11-06 — Docs seeded, not empty.** Phase 1 says create empty `OPEN_QUESTIONS.md`, `ASSETS_NEEDED.md` and `DECISIONS.md`. They are seeded with the known items from CONTENT.md section 9 and the build decisions, so the owner has an actionable checklist.
- **2026-11-06 — Analytics deferred.** `PUBLIC_GA_ID` is not wired yet. The privacy page and the conditional gtag loader arrive in Phase 7; no third-party requests are made now.
- **2026-11-06 — Temporary home page.** Phase 1 ships a branded page using only CONTENT.md facts (name, tagline, descriptor, cities, lab/branch statement). It is replaced by the full 11-section home page in Phase 3.
- **2026-11-06 — Tests and audits.** `npm run build` runs `astro check --minimumFailingSeverity warning` so warnings fail the build. `npm run links` uses linkinator on `dist/`; Lighthouse CI uses a local static server and a filesystem report so reports are not uploaded publicly.
- **2026-11-06 — Lighthouse browser on the owner's machine.** Only Microsoft Edge is installed, so `npm run lighthouse` and `npm run audit` need a browser path:
  `CHROME_PATH="C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe" npm run audit`.
  No project change is needed; CI and any machine with Chrome work without it.

## Phase 2 — site shell

- **2026-11-06 — One validation layer.** All four collections plus the process steps are parsed once in `src/lib/content.ts`. A duplicate slug, invalid path or wrong parent fails the build with a short list rather than a stack trace. `src/config/site.ts` imports `offices` from this module, so the office schema is no longer duplicated.
- **2026-11-06 — `src/data/process.json` added.** BRIEF section 6 lists four data files, but the four process steps are shared content used by the home page. They live in data rather than being hard-coded in `ProcessSteps.astro`, following the rule that content lives in `src/data/`.
- **2026-11-06 — `examples` added to `services.json`.** The home page needs three or four representative instruments per discipline. They are selected from the CONTENT.md lists and do not add facts.
- **2026-11-06 — The five companies stay unpublished.** Phase 2 specifies `published: false` for all seeds. `PUBLIC_SHOW_DRAFTS=1` makes them visible in development, including the Products dropdown. A production build shows "Catalogues coming soon" and the All products link until the owner publishes a company (see `OPEN_QUESTIONS.md` item 6).
- **2026-11-06 — Top bar height and touch targets.** The bar remains 36px on desktop as specified. Its links carry a 44px hit area using negative block margins, and the bar becomes 44px under 640px. Footer phone and email links are 44px rows. This follows the 44px tap-target rule without changing the desktop bar height.
- **2026-11-06 — Button styles live in `global.css`.** `.btn` is a design-system primitive used by most components. Keeping it global ships the rules once and guarantees identical focus, hover and crimson-surface behaviour; every other component keeps scoped styles.
- **2026-11-06 — Header interactions are vanilla.** Desktop dropdowns use disclosure buttons with `aria-expanded`, click and hover opening, ArrowDown, Escape and outside-click closing. The mobile sheet is a native `<dialog>` with focus trapping, Escape and a pinned WhatsApp button. No client framework.
- **2026-11-06 — WhatsApp glyph inline.** The glyph path is from Simple Icons (CC0), inlined to avoid a dependency. It inherits `currentColor`, so no WhatsApp green enters the palette.
- **2026-11-06 — Link checks deferred to Phase 4+.** The shell links to routes that arrive in Phases 4 to 6 (`/about/`, `/services/`, `/products/`, `/clients/`, `/contact/`, `/privacy/`). `npm run links` will report those until the pages exist; `npm run build` is the Phase 2 gate.

## Phase 3 — home page

- **2026-11-06 — Owner-supplied logo variants replace the CSS filter.** `public/Logo/JIE_light.svg` (white plate, dark lettering) is used on light surfaces; `public/Logo/JIE_dark.svg` (transparent, white gauge, rose lettering) is used on the crimson footer. `scripts/brand-assets.mjs` optimises both into `src/assets/brand/jie-logo-light.svg` and `jie-logo-dark.svg`; `Logo.astro` takes `tone="onLight" | "onDark"`. The Phase 2 white `filter` is removed, and the master in `design/` is no longer the brand source. `AGENTS.md` still describes the old single master; this decision supersedes it until the owner updates the rule.
- **2026-11-06 — Owner-supplied favicon set is the source.** `public/Logo/favicon/` is copied to the site root as `favicon.ico`, 16/32 PNGs, `apple-touch-icon.png` and the two Android icons. The generated `favicon.svg`, `favicon-32.png` and `favicon-192.png` are deleted. `logo-512.png` is the 512 Android icon; `og-default.png` is rebuilt from the light SVG on white with a crimson bar. `site.webmanifest` is written by the script because the supplied one has empty `name`/`short_name`. Note the supplied ICO/PNG icons depict the gauge mark only, while the SVG logo includes the wordmark; that is the owner's artwork and is left untouched.
- **2026-11-06 — Home copy lives in `src/data/home.json`.** Every home string is validated at build by `homeSchema` in `src/lib/content.ts`, so the owner can edit copy without touching templates, and a missing field fails the build. Facts come only from `CONTENT.md`.
- **2026-11-06 — Why JIE shows four points, not five.** The brochure's first bullet is the ISO/IEC 17025 line, which is unconfirmed (no certificate, obsolete edition). The section renders Experienced team, State-of-the-art facility, Prompt and cost-effective service, and Traceability. Adding the fifth point requires a current certificate.
- **2026-11-06 — Final CTA is a crimson panel inside a background section.** The page already has a full crimson band (on-site calibration) and a crimson footer. A third full-width crimson band would create heavy repetition, so the closing call to action is a rounded crimson panel on `--bg`. No two crimson bands touch.
- **2026-11-06 — Client and industry sections use text wordmarks.** Customer logos are not supplied or cleared for use, so the marquee renders the featured client names as text with gold dot separators, and `Industries` uses five sector groups from CONTENT.md. No logo images are invented.
- **2026-11-06 — Marquee is CSS-only.** The track duplicates the list once (`aria-hidden` on the copy) and animates with a 50% `translateX` loop; it pauses on hover/focus and becomes a single static wrapped list under `prefers-reduced-motion`. Two overflow bugs were fixed during QA: the reduced-motion track needed `display: block` with a full-width group, and long client names needed `white-space: normal` at 360px. No JavaScript is shipped for it.
- **2026-11-06 — Footer clears the floating WhatsApp button.** The footer's bottom bar reserves right padding equal to the fixed button plus its margin, so the Privacy link is never covered at the end of the page.
- **2026-11-06 — Home JS and CSS budgets met.** The home page ships one small script bundle (1.1 KB gzip, header behaviour only); the marquee, carousel facade and cards ship no JS. CSS is 6.5 KB gzip site-wide.
- **2026-11-06 — Lighthouse measured with Chromium, not Edge.** Phase 1 noted Edge was the only browser; a Chromium install is now available at `C:/Users/Vighnesh Nilajakar/AppData/Local/Chromium/Application/chrome.exe`, so `CHROME_PATH` can point at it for faster, more representative runs. Scores on the home page: 100/100/100/100, LCP 0.8 s, CLS 0, TBT 0 ms.
- **2026-11-06 — Draft companies stay hidden on the home page.** With all five `published: false`, the Products section shows a bordered empty-state panel ("Catalogues coming soon") with a WhatsApp button, rather than an empty carousel. `PUBLIC_SHOW_DRAFTS=1` shows the real carousel for review.

## Phase 4 — services

- **2026-11-06 — Page copy lives in `services.json`.** Phase 2's file held only slug, path, title, summary, examples, instruments and FAQ. It now also carries `heading`, `metaTitle`, `metaDescription`, `intro[]`, `listTitle`, `notes[]`, `onSiteNote` and `related[]`, so all ten service pages render from data with no strings in templates. `serviceSchema` validates: unique slugs, path derived from kind and parent, `metaTitle` ≤ 60, `metaDescription` ≤ 155, `related` slugs that exist and never self-reference, and 3–5 FAQs. A bad entry fails the build.
- **2026-11-06 — `src/data/services-page.json` added.** BRIEF section 6 lists data files but not one for the services hub. Its heading, intro and five FAQs are content, so they live in data and are validated by `servicesPageSchema`.
- **2026-11-06 — One shared template, `components/services/ServicePage.astro`.** All eleven inner service pages use it. Blocks render conditionally, so a page without instruments or notes is shorter rather than padded. Backgrounds alternate `bg`/`surface` in render order via a `nextTone()` helper, which keeps contrast between adjacent sections without per-page tone props.
- **2026-11-06 — `PageHeader.astro` and `CtaPanel.astro` are shared.** Both are needed by every service page and will be reused in Phases 5–7. `PageHeader` owns breadcrumbs, H1, lead paragraph and the action slot; `CtaPanel` is the crimson closing panel with WhatsApp and phone. Rebuilding either per page would drift.
- **2026-11-06 — No `FAQPage` JSON-LD.** Service pages emit `Service` plus `BreadcrumbList` only. AGENTS.md lists the JSON-LD types this site uses, and FAQ rich results are restricted by Google to well-known government and health sites. The FAQ markup still ships as accessible `<details>` content.
- **2026-11-06 — Breadcrumb separator moved to `li:not(:last-child)::after`.** With `li + li::before`, a wrapped crumb started a new line with a separator in front of it. The separator now trails the previous crumb, so wrapped mobile breadcrumbs read correctly. `aria-current="page"` on the last item is unchanged.
- **2026-11-06 — The civil page shows cement and construction customers.** It is the only discipline whose sector maps directly onto a named client group in CONTENT.md, so it carries a text-wordmark list of those eight customers. No other service page gains a client list, to avoid repeating the Clients page due in Phase 6.
- **2026-11-06 — Instrument lists stay verbatim; intros are shortened.** Each discipline's `instruments` array reproduces the CONTENT.md list word for word. The second intro paragraph only names a representative subset, because the full list in prose read as a wall of text on mobile. No instrument was added, removed or reworded.
- **2026-11-06 — No push at the end of Phase 4.** The build is committed locally only. Deploying now would publish a site whose header and footer link to `/products/`, `/clients/`, `/about/`, `/contact/` and `/privacy/`, which do not exist until Phases 5–7. `npm run links` stays red for the same reason.
