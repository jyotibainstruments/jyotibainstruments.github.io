## GitHub Pages deployment fix

- **2026-11-06 — Pages switched to workflow deployment.** A push to `main` failed in GitHub's default "Deploy from branch" pipeline: `actions/jekyll-build-pages` treated `.astro` files as YAML front-matter and could not build an Astro repo at all (failed at `c371384`). The repo already had the correct `deploy.yml` from the Phase 1 kit, but a `workflow_dispatch` trigger does nothing while Pages still points at the `main` branch. `actions/configure-pages@v5` with `enablement: true` was added to the build job so the run itself upgrades the setting to `build_type: workflow` using the workflow's `pages: write` token. If the token lacks that permission on the first attempt, the manual step is: Settings → Pages → Build and deployment → Source: **GitHub Actions**. `public/.nojekyll` is shipped in `dist/` as a belt-and-braces guard. **Outcome confirmed:** both the `b9a0f96` (run #2) and `617bd69` (run #3) "Deploy to GitHub Pages" runs succeeded and the site serves the workflow build; no manual step was needed. GitHub still also fires a legacy "pages build and deployment" run on each push, which fails for this repo and is harmless as long as the "Deploy to GitHub Pages" workflow run succeeds — treat red on that other run as noise, not as a deploy failure.
